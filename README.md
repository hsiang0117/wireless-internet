# 无线网络共享 · Wireless Internet

**在电脑不开热点的情况下，把电脑的网络共享给安卓手机。**

电脑通过有线网络上网，Wi-Fi 连接**手机开启的热点**；程序利用无线 ADB 和 gnirehtet，把手机应用的网络请求送到电脑，再由电脑访问互联网。电脑的 Windows「移动热点」保持关闭，无需先插 USB。

当前版本：**1.9.0**。原创代码和文档采用 [MIT License](LICENSE)。

## 原理说明

手机热点提供的是手机与电脑之间的无线局域网。电脑以可用的有线网络作为上游，中继实际的连接路径仍受电脑当前路由和 VPN 规则影响。

```mermaid
flowchart LR
    A["手机应用"] <--> V["手机 gnirehtet VPN"]
    V <-->|"无线 ADB 通道 · adb reverse"| R["电脑 gnirehtet 中继"]
    R <--> S["电脑当前路由 / VPN 规则"]
    S <--> E["电脑有线网络（上游）"]
    E <--> N["互联网"]
```

1. **建立局域网链路**：手机开启热点，电脑 Wi-Fi 作为客户端连接该热点。电脑自身不开热点，也不需要开启 Windows 的互联网连接共享（ICS）。
2. **建立无线调试连接**：通过 Android 原生无线调试完成配对和 TLS 连接，程序经手机热点网关访问手机。
3. **转发手机流量**：手机端 gnirehtet 使用 Android VPN 接口接收应用的 IPv4 数据包，经 `adb reverse` 送到电脑中继；中继在电脑上建立对应的 TCP／UDP 连接，响应再沿原路返回。
4. **提供桌面控制和监控**：本程序负责绑定、连接、断开、托盘、实时日志、流量采样及双端失联保护。

**电脑不开热点，手机仍需要开热点。** 当前方案还要求手机同时连接 Wi-Fi，以便系统允许开启原生无线调试；手机必须支持 Wi-Fi、热点与无线调试并存。

电脑开启 VPN／TUN 时，中继的出站连接由电脑当前的路由和 VPN 规则决定。本工具不修改这些规则，也不保证全部流量使用某个代理节点。

## 功能

- 在桌面界面开始连接、断开连接，主动更换或重新绑定手机。
- 连接与断开在控制台显示当前阶段，失败时可结合阶段与具体提示定位问题。
- 关闭窗口收起到系统托盘；托盘右键可开始、断开和退出。
- 实时查看中继 TCP／UDP 连接事件、目标 IP 和端口，以及当前 TCP 连接列表。
- 显示本次 VPN 接口流量、上传／下载速度、连接时长和网速曲线。
- 主窗口显示且未最小化时，手机流量统计约每 3 秒采样；最小化或收起到托盘时暂停非安全手机采样，后台共享和保护继续运行。
- 电脑与手机各有会话保护，默认在持续失联约 30 秒后结束共享。
- 日志只在内存中滚动显示，不持续写入日志文件；高频消息分批绘制。

## 运行条件

| 项目 | 要求 |
| --- | --- |
| 电脑系统 | Windows 10 2004 及以上或 Windows 11，x64，.NET Framework 4.8 |
| 电脑网络 | 可上网的有线网络，以及能连接手机热点的 Wi-Fi 网卡 |
| 手机系统 | Android 11+，机主用户（user 0），支持原生无线调试 |
| 手机网络能力 | 能同时保持 Wi-Fi、热点和无线调试开启 |
| 手机 VPN | 使用 gnirehtet；同一用户下的其他手机 VPN 应先断开 |

桌面程序附带 ADB 和 gnirehtet 运行组件，普通使用无需安装 Android Studio、Java 或 Rust，也无需手工运行启动／停止脚本。

当前实际验证集中在 Android 16 手机及现有 Windows 环境，其他品牌、系统和厂商限制仍需分别验证。

## 获取与启动

从本仓库下载 ZIP 并解压，保留完整目录结构，运行 `WirelessInternet.exe`。使用安装包时，可通过桌面或开始菜单快捷方式打开。

首次运行会打开手机绑定向导；也可从主界面或托盘点击 **「更换/绑定手机」**。配置通过向导保存，不需要手工填写手机标识。`wireless-config.example.json` 仅作为未绑定的配置示例。

## 首次配置

### 1. 准备网络

1. 电脑连接有线网络，确认电脑自身能正常上网。
2. 手机连接一个可信 Wi-Fi，再开启手机热点。
3. 让电脑 Wi-Fi 连接这台手机的热点，电脑 Windows「移动热点」保持关闭。
4. 在手机「开发者选项 → 无线调试」中开启开关，按系统提示允许当前可信网络。后续保持手机 Wi-Fi、热点和无线调试开启。

如果手机提示「先连接 Wi-Fi」或无法同时保持 Wi-Fi 与热点，请先检查手机系统是否支持这种组合。手机所连 Wi-Fi 是否完成网页登录，与无线调试链路是否建立是两件事；共享成功后仍需实际测试手机上网。

### 2. 完成配对

1. 打开电脑上的「更换/绑定手机」向导。
2. 在手机无线调试页选择「使用配对码配对设备」。
3. 将该页面的**配对端口**与**六位配对码**填入向导，点击「开始配对」。操作期间保持手机配对码页面打开。
4. 配对成功后，返回手机无线调试**主页面**，将主页面的**连接端口**填入连接验证区，点击「已配对，检测并保存」。

| 填写位置 | 手机上对应的信息 |
| --- | --- |
| 配对地址／端口、配对码 | 「使用配对码配对设备」弹窗 |
| 连接地址／端口 | 「无线调试」主页面的「IP 地址和端口」 |

**配对端口和连接端口不同，不能混用。** 向导允许只填写端口，也可填写 `IP:端口`。

手机主页面可能显示它连接 Wi-Fi 时的地址。电脑通过手机热点访问时，程序会使用热点网关替换地址，并保留对应端口，向导会显示实际目标地址。多块 Wi-Fi 网卡时，可在高级项指定正确网卡索引。

已经在这台电脑配对过的手机，可直接填写当前连接端口并检测保存。配对码只用于本次操作，不写入配置或日志；ADB 会按其正常机制保存本机授权凭据。

### 3. 开始共享

1. 手机已安装 gnirehtet 时，先确认 **「始终开启 VPN」** 和 **「阻止未使用 VPN 的连接」** 两个开关均关闭。首次尚未安装时，先按后续步骤安装并授权，再确认这两项均关闭。
2. 在电脑点击「开始连接」。首次使用可能需要安装随附的 gnirehtet APK，在手机上按提示允许安装。
3. 手机出现 gnirehtet VPN 连接请求时，手动允许。
4. 等电脑显示连接正常、保护心跳正常，再测试手机网页和常用应用。

两个 VPN 限制开关在整个使用期间均须保持关闭；开始和断开连接时程序都会检查，开启它们也可能影响失联守护关闭手机 VPN。

手机移动数据可以保持关闭。不同应用对 Android 网络状态的判断可能不同，应分别确认常用应用能否联网。

若手机拒绝 APK 安装，按厂商提示手动允许相关安装／调试权限，或手动安装 `gnirehtet-rust-win64/gnirehtet.apk`。程序不会代为修改手机系统开关。

## 日常使用

### 连接、断开与托盘

- 每次连接前，保持电脑有线网络可用、电脑 Wi-Fi 已连接手机热点，以及手机 Wi-Fi／热点／无线调试开启。
- 点击「断开连接」，确认共享结束后，再手动关闭手机无线调试和热点。
- 窗口右上角 **X 只收起到托盘**；双击托盘图标恢复窗口。
- 从托盘选择「退出」时，程序会先断开共享，再退出桌面程序。

### 更换手机或更新端口

1. 先断开当前共享。
2. 更换手机时，关闭旧手机无线调试，避免 ADB 自动重连到旧设备。
3. 准备新手机的 Wi-Fi、热点与无线调试，让电脑连接新手机热点。
4. 打开「更换/绑定手机」，按需配对，再检测并保存。
5. 保存成功后，点击「开始连接」。

检测失败或取消向导会保留旧绑定。每次只使用一个绑定，不支持多部手机同时共享；程序不会删除旧手机的系统配对记录。

手机无线调试端口变化时，程序优先通过 mDNS 重新发现。发现失败时，可在断开状态下重新填写当前主页面的连接端口；通常不需要重新配对。

## 失联保护与流量统计

电脑监控约每 5 秒检查共享状态，并与手机本地守护按会话交换保护心跳。短暂断线会尝试恢复，持续失联后，默认在最后一次成功心跳约 30 秒后结束本次共享。最小化、收起到托盘或暂停界面统计都不会停用这项保护。

保护检查的是调试通道、中继、手机 VPN 等共享状态，**不是公网可用性探测**。手机深睡、后台进程被系统终止或厂商限制可能使退出延迟或失效；正常结束仍应使用「断开连接」或托盘「退出」。

流量来自手机 VPN 接口计数，主窗口显示且未最小化时约每 3 秒采样，速度为最近采样间隔的平均值，包含协议开销，**不等同于运营商计费**。缓存速度最多保留 4 秒有效；过期时显示「—」。最小化或收起到托盘后不再发起新的非安全手机统计查询；已在途的查询允许完成。恢复窗口时先重新建立速度基线，到下一个完整采样间隔后再显示速度。暂停期间仍在传输数据，恢复后累计流量以手机接口计数为准。

连接日志仅保留最近内容；收起窗口或切到连接列表时，日志文字绘制会暂停，后台共享与保护继续运行。

连接、失联保护和统计分别判断。偶发统计查询失败时保留最后有效的累计流量，速度显示「—」，不会仅因统计失败要求重连；保护心跳异常会单独显示。统计恢复后重新建立速度基线，避免把中断期间的流量当成瞬时网速。

## 兼容性与常见问题

### 电脑一定要开热点吗？

不需要。电脑连接的是**手机热点**。手机热点承载手机与电脑的局域网连接，手机使用电脑提供的互联网连接，具体出站路径受电脑路由和 VPN 规则影响。

### 需要先接 USB 吗？

不需要。本版使用 Android 原生无线调试配对，不采用 USB 引导或固定 5555 端口的旧无线 ADB 方案。

### 电脑开着 VPN／TUN 能用吗？

1.4.2 已修复部分虚拟网卡返回空 `InterfaceMetric` 导致启动和保护检查失败的问题，实际物理网卡的路由指标仍严格校验。

已在当前 Clash Verge／Mihomo TUN 开启环境验证连接、断开、重连和手机 HTTPS：正常证书校验、HTTP 200、对应中继连接及 VPN 双向流量增长均通过，保护心跳也持续超过 30 秒。其他 VPN、驱动和网络组合仍需实测。

### 网卡或路由检查失败怎么办？

确认电脑 Wi-Fi 连接的是目标手机热点，有线网络可用；多网卡时检查向导中的网卡索引。程序要求有线 IPv4 默认路由优先于手机热点，只检查，不自动修改路由或网卡优先级。

### 手机没有 VPN 图标，或某个应用仍不上网？

不同系统对 VPN 图标和网络状态的显示存在差异。结合电脑的连接／保护状态、流量变化和手机实际访问结果判断；单个图标不能证明整个共享链路健康。应用兼容性应单独检查。

### 支持 IPv6 和高 DPI 吗？

底层 [gnirehtet](https://github.com/Genymobile/gnirehtet/tree/v2.5.1) 转发 IPv4 TCP／UDP，不支持 IPv6。

界面以 96 DPI 为设计基准，已在 150%／100% 双屏环境验证布局。不同倍率屏幕间由 Windows 整体缩放，可能略有插值模糊；200% 尚需在目标电脑验证。

## 配置、升级与卸载

`wireless-config.json` 保存本机手机绑定，`state/` 保存当前运行状态；运行期间不要手工编辑或删除会话文件。它们均被 Git 忽略，仓库不携带已有配对、会话或 ADB 私钥。

更新程序文件、执行 `git pull`、运行安装包或卸载前，先正常断开共享并从托盘退出，避免运行中的程序文件被占用。

安装器发现目标目录仍有共享会话时会拒绝继续。升级保留本机配置；卸载保留无线配置，不删除全局 `.android` 凭据，也不从手机移除 APK 或配对记录。

## 开发与测试

电脑端界面、连接控制和保护监控使用 **C# 5／.NET Framework 4.8**。手机本地守护内容内置在程序中，按会话下发，临时传输文件随后清理。

| 路径 | 用途 |
| --- | --- |
| `source/` | 桌面界面、连接控制、监控与嵌入式手机守护源码 |
| `support/` | 电脑后台组件与图标 |
| `gnirehtet-rust-win64/` | gnirehtet 中继、APK 及上游许可证 |
| `platform-tools/` | Android 平台工具及随附声明，运行共享时使用 ADB |
| `tests/` | 使用合成数据和假中继进程的离线回归 |
| `packaging/` | 发布流水线、安装包构建和包内源码重编校验 |
| `.github/workflows/` | GitHub Actions 发布检查及构建产物 |

1.5.0 完成第一轮结构调整：界面操作由独立协调器统一管理开始、断开、配置和退出；连接、保护及统计状态分离；短命令统一使用有输出上限、双流排空和超时控制的执行器。中继与保护监控仍保留独立进程，收起窗口不会停止共享。

1.5.1 减少非安全手机统计查询，并将手机守护的小文件读取改为 shell 内建操作，活性记录约每 5 秒写入。默认 30 秒失联阈值与约 5 秒保护心跳保持不变。这些调整减少外部命令执行和活性标记写入，尚未测量实际电量降幅。

1.6.0 整理连接生命周期：`ConnectionController` 按阶段协调开始、断开和失败处理，控制台显示阶段进度，内部阶段结果记录失败位置和结果消息。手机命令移入 `AndroidDeviceClient`，通用回复解析由 `AndroidProtocol` 提供；会话持久化移入 `RuntimeSessionStore`，进程身份核验和生命周期操作移入 `OwnedProcessManager`。`RuntimeContext` 保留原调用入口，逐步转发到这些职责明确的组件。

本轮保留原有操作锁、执行顺序和状态提交／清理边界。失败清理仍须核对会话 token 和进程 PID、启动时间及路径；已经提交的会话按原恢复流程保留必要资源，供正常断开或重试处理。默认 30 秒失联保护、约 5 秒保护心跳以及 1.5.1 的前台三秒统计／后台暂停行为保持不变。

1.7.0 整理桌面监控与显示：`SystemSessionObservationSource` 负责只读系统观察，`PhoneTrafficTracker` 管理统计与采样缓存，`MonitorSnapshotAssembler` 组合快照；`Backend` 保留原调用入口。`ConsoleLogView` 独立处理有界日志批次、去重及阅读位置，自绘控件与视觉值由 `DashboardControls`／`UiVisualStyle` 提供。原有布局、DPI、日志限额、三秒采样和后台暂停行为保持不变；操作状态仍由同一个 `UiOperationCoordinator` 管理。

1.8.0 将操作阶段和最终结果通过独立的本机命名管道传给界面，与可限流的控制台日志分开。界面显示当前连接／断开阶段，失败时显示具体阶段与原因；未收到完整且匹配的结果时显示“操作结果未确认”，不会仅凭进程退出码报告成功。最终结果仍需与进程退出码核对；丢失界面连接不会中断已经开始的安全清理。

1.9.0 统一桌面和 worker 的网络／会话字段定义，以及 worker 和绑定向导的配置文档。沿用现有 JSON 字段名、类型、缺省值和未知字段保留规则，无需重新配对。GUI 仍只读取原有观察字段，worker 仍严格校验完整会话；绑定向导保留界面索引容错与明确保存后才写入默认值的行为。原子写入、锁、采样和 30 秒失联保护保持不变。

源码提供三个独立的 MSBuild 项目和 solution，共享源文件按组件编译，运行时不新增共享 DLL。编译说明见 [source/BUILD.md](source/BUILD.md)，离线测试方法见 [tests/README.md](tests/README.md)。默认测试只运行操作结果通道和共享数据模型的快速检查；历史安全回归和需要额外环境的检查可按需运行。离线回归不调用真实 ADB，也不修改网络设置。

发布流程使用 [packaging/Run-Release.ps1](packaging/Run-Release.ps1)，串联快速检查、Release 构建、安装包编译和包内源码重编。重编结果须与三个已打包 EXE 及其运行配置逐一匹配；流水线同时核对载荷清单和安装包 SHA-256。历史全量回归通过 `-FullRegression` 显式选择；手机、DPI 和需要时的安装行为仍单独验收。

[GitHub Actions 发布检查](https://github.com/hsiang0117/wireless-internet/actions/workflows/release.yml) 在 main 推送、PR 和手动运行时执行，成功后可在运行页面下载安装包及校验值，诊断报告独立保存。手动运行可勾选历史全量回归。构建方法和本地输入要求见 [packaging/README.md](packaging/README.md)。
